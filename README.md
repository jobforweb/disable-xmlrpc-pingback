# Disable XML-RPC & Pingback Completely

Небольшой автономный плагин WordPress, который полностью отключает протокол XML-RPC, pingback/trackback, HTTP-заголовок `X-Pingback` и тег `<link rel="pingback">` в клиентской части сайта. Не зависит от темы оформления и от WooCommerce: активируется и отключается одной кнопкой, не сохраняет данные в базе и не создаёт таблиц.

## 1. Назначение

- убрать один из классических векторов атак и источник нагрузки на `xmlrpc.php` (brute-force, DDoS через `system.multicall`, спам-пингбэки);
- закрыть утечку информации о механизмах публикации (RSD, Windows Live Writer, pingback URL);
- обеспечить одинаковое поведение на всех типах записей, включая страницы WooCommerce, без правки шаблонов.

Плагин работает на уровне хуков WordPress и не модифицирует файлы ядра, темы или `.htaccess`.

## 2. Техническое описание

### 2.1. Уровни отключения

| Уровень | Хук / механизм | Результат |
| --- | --- | --- |
| Протокол XML-RPC | `xmlrpc_enabled` → `__return_false` | Ядро отклоняет любые запросы к `xmlrpc.php` как отключённые |
| Список методов | `xmlrpc_methods` → пустой массив | Даже при обходе предыдущего фильтра ни один метод не доступен |
| Pingback на записях | `pings_open` → `__return_false` с приоритетом `PHP_INT_MAX` | Pingback и trackback закрыты для всех материалов; фильтр имеет максимальный приоритет, чтобы переопределить другие плагины |
| HTTP-заголовки | `wp_headers`, сравнение имён через `strcasecmp()` | `X-Pingback` удаляется независимо от регистра ключа |
| Discover-ссылки | `remove_action( 'wp_head', 'rsd_link' )`, `remove_action( 'wp_head', 'wlwmanifest_link' )` | Не выводятся ссылки RSD и Windows Live Writer, также использующие XML-RPC |
| `bloginfo()` | `bloginfo_url` с приоритетом 11 | `bloginfo( 'pingback_url' )` возвращает пустую строку |
| Готовый HTML | `template_redirect` → `ob_start()` + `preg_replace()` | Тег `<link rel="pingback">` вырезается из финальной разметки, в том числе если он жёстко прописан в `header.php` темы |

### 2.2. Особенности реализации

- Буфер вывода запускается только для фронтенд-HTML: админка, ленты, trackback, `robots.txt` и JSON-запросы исключены проверками `is_admin()`, `is_feed()`, `is_trackback()`, `is_robots()`, `wp_is_json_request()`. Это исключает случайную порчу ответов не-HTML типов.
- Регулярное выражение учитывает одинарные и двойные кавычки, пробелы вокруг `=`, регистр и самозакрывающиеся теги: `<link ... rel='pingback' ... />`.
- Все функции имеют префикс `dxp_`, что исключает конфликт с другими плагинами. Анонимные функции заменены именованными — их можно снять через `remove_filter()`/`remove_action()` при интеграции.
- Загрузка переводов выполняется на хуке `init` через текстовый домен `disable-xmlrpc-pingback` (папка `languages/` зарезервирована).
- Прямой доступ к файлу плагина заблокирован проверкой `ABSPATH`.
- Константа `DXP_VERSION` может быть переопределена до подключения плагина (например, в `wp-config.php`).

## 4. Установка

### 4.1. Через административную панель

1. Загрузите архив плагина через **Плагины → Добавить новый → Загрузить плагин**.
2. Активируйте **Disable XML-RPC & Pingback Completely** в списке установленных.

### 4.2. Вручную (FTP / файловый менеджер)

1. Создайте каталог `/wp-content/plugins/disable-xmlrpc-pingback/`.
2. Поместите в него `disable-xmlrpc-pingback.php` и `index.php`.
3. В админке откройте **Плагины → Установленные** и активируйте плагин.

### 4.3. Альтернатива: код в дочерней теме

Если дочерняя тема уже используется, тот же результат можно получить без отдельного плагина. Откройте `functions.php` дочерней темы, добавьте код в конец файла **до** закрывающего тега `?>` (лучше — без него):

```php
add_filter( 'xmlrpc_enabled', '__return_false' );
add_filter( 'pings_open', '__return_false', PHP_INT_MAX );

add_filter( 'wp_headers', function( $headers ) {
	foreach ( array_keys( $headers ) as $name ) {
		if ( 0 === strcasecmp( 'X-Pingback', (string) $name ) ) {
			unset( $headers[ $name ] );
		}
	}
	return $headers;
} );

remove_action( 'wp_head', 'rsd_link' );
remove_action( 'wp_head', 'wlwmanifest_link' );

add_filter( 'bloginfo_url', function( $output, $property ) {
	return 'pingback_url' === $property ? '' : $output;
}, 11, 2 );

add_action( 'template_redirect', function() {
	if ( is_admin() || is_feed() || is_trackback() || is_robots() || wp_is_json_request() ) {
		return;
	}
	ob_start( function( $html ) {
		$result = preg_replace( '/<link\b[^>]*\brel\s*=\s*(["\'])pingback\1[^>]*>\s*/i', '', $html );
		return null === $result ? $html : $result;
	} );
}, 0 );
```

**Важно:** используйте только один вариант — плагин **или** код в теме. Одновременное применение дублирует фильтры и осложняет диагностику. Преимущество плагина: он не зависит от оформления, не затирается при обновлении темы и отключается одной кнопкой.

## 5. Проверка работоспособности

После активации сбросьте кэш (плагин кэширования, CDN, браузер) и выполните проверки:

```bash
# Заголовок X-Pingback должен отсутствовать
curl -sI https://example.com/ | grep -i 'x-pingback'

# xmlrpc.php должен отвечать отказом
curl -s -X POST https://example.com/xmlrpc.php

# Тег pingback не должен встречаться в HTML
curl -s https://example.com/ | grep -i 'pingback'
```

Дополнительно откройте исходный код любой страницы записи или товара WooCommerce (`Ctrl+U`) и убедитесь, что в `<head>` нет `rel="pingback"`, `EditURI` и `wlwmanifest`.

Если тег остался после очистки кэша: проверьте, не включён ли дублирующий код в `functions.php` темы, не кэширует ли CDN старый HTML и не добавляет ли тег сторонний плагин после `template_redirect` (например, через `wp_footer`). В таком случае достаточно проверить итоговый HTML на наличие строки `pingback`.

## 6. Рекомендации по эксплуатации

- После включения обязательно очистите кэш страниц и объектный кэш — иначе браузер может показывать старую разметку.
- Не используйте вместе с плагинами, которые напрямую редактируют `xmlrpc.php` или добавляют правила в `.htaccess`: это дублирует функциональность.
- Если сайт использует Jetpack или другие сервисы, работающие через XML-RPC, отключение нарушит их связь с wordpress.com. В таком случае откажитесь от активации или используйте точечное закрытие pingback.
- На мультисайте активируйте плагин на каждом сайте отдельно или сетевой активацией с учётом совместимости с Jetpack.
- Плагин не хранит опции, поэтому `uninstall.php` не требуется: при удалении не остаётся мусора в базе.

## 7. История изменений

### 1.1.0

- Заголовок плагина приведён к правилам WordPress: добавлены `Text Domain`, `License`, `License URI`, `Requires at least`, `Requires PHP`, удалено недопустимое поле `Tags`.
- Анонимные функции заменены именованными с префиксом `dxp_`.
- Добавлен фильтр `xmlrpc_methods` и отключение `wlwmanifest_link`.
- Удаление `X-Pingback` стало регистронезависимым.
- Буфер вывода ограничен фронтенд-HTML и защищён от ошибок `preg_replace()`.
- Добавлены `readme.txt`, техническая документация, проверки работоспособности.

### 1.0

- Первоначальная версия: `__return_false` для `xmlrpc_enabled` и `pings_open`, удаление `X-Pingback`, `rsd_link` и тега pingback из HTML.
